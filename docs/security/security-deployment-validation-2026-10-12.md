## 설치된 FFmpeg와 접근 정책

**시스템에 설치된 FFmpeg 7.1.5와 시스템 라이브러리**로 다음 검사를 통과했다.
빌드 전 검증처럼 임시 라이브러리를 올려 실행한 결과가 아니다.

- 합성 320×240 H.264 10프레임의 MP4 생성·디코딩, JPEG 생성·디코딩.
- 세 IDX 구간이 두 스트림 ID를 재사용하는 제한된 VobSub fixture 처리.
- Floodfill은 PGM/gray, hqdn3d는 MJPEG 입력으로 네 프레임의
  `32×24 → 64×48 → 32×24 → 64×48` 변화를 처리했다. 필터 재초기화를 끄고
  필터 worker 2개로 실행했으며, 필터 전후 크기와 출력 프레임 수를 확인했다.

이 합성 미디어 시험은 카메라 센서를 점유하지 않았다. 운영 앱의 boot ID·PID·
재시작 횟수가 유지됐고 임시 파일은 제거했다. 실제 센서 영상은 운영 앱과
사용자의 마지막 웹 화면 확인으로 검증했다. 전체 FFmpeg FATE나 모든 할당 실패·
동시성 경로를 시험한 것은 아니다.

실제 **OpenSSH 10.6p1**의 socket activation, 공개 키 전용 인증, root 로그인
금지와 `rpiadmin` 허용 정책을 확인했다. root 및 공개 키 없는 접속은 거부됐고,
사용자 이름 검증과 **131,072바이트 SFTP 왕복 전송·해시 비교**를 통과했다.

운영 RTSPS의 TLS·비인증 거부 **16개 검사**, OPTIONS 세션 선택 헤더 정책
**5개 검사**를 재부팅 전후 모두 통과했다. 빈 헤더가 파서에서 제거되는 경우와
인증이 필요한 실제 선택 값을 구분했다. 인증된 RTSP 미디어 수신·복호화 및 세션
격리 전체 시험은 [이전 검증](rtsp-deployment-validation-2026-10-11.md)의
별도 결과이며 이번에 다시 실행했다고 표시하지 않았다.
