## 설치 및 신원 확인

- 기존 `scripts/install-ssd.sh`의 설치 완료 시각은 **2026-10-11T19:22:34Z**이다.
  설치 기록의 압축 이미지 SHA-256과 최종 산출물의 실제 해시가 같다.
- 사용자의 새 이미지 부팅 확인과 설치 기록을 근거로 재설치 후 바뀐 SSH 키를
  별도 검증 파일에 고정했다. 접속 직후 이미지 ID·프로필·기존 보드 식별자와
  USB SSD 루트를 확인했다. 새 파일시스템 UUID는 최초 접속에서 기록하고
  재부팅 내내 동일함을 검사했다. 이전 이미지의 키·결과는 덮어쓰지 않았다.
- 설치된 OpenSSH는 **10.6p1**이다. SSH/SCP/sshd/sshd-session/sshd-auth/keygen/
  SFTP server, 앱과 RTSP 라이브러리, 개발용 소스·테스트를 합쳐 **12개 파일**의
  해시가 이전에 검증한 실제 WIC와 모두 일치했다.
- 장치에서 TLS 공개 인증서를 SSH를 통해 수집한 뒤 HTTPS·RTSPS 접속에서
  동일 인증서를 고정했다. 직접 IP 접속의 호스트 이름 검사만 예외로 두었으며,
  인증서 체인·유효기간 검사와 DER 해시 비교는 유지했다.

## 설치된 SSH 서버 검증

| 검사 | 결과 |
| --- | --- |
| 실제 SSH 접속 | rpiadmin의 기존 개인 키로 성공 |
| socket activation | `sshd.socket` active/enabled, 재부팅 후에도 접속 성공 |
| 유효 인증 정책 | `AuthenticationMethods publickey`, `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin no`, `AllowUsers rpiadmin` |
| 계정 비밀번호 | locked 상태 확인 |
| root 로그인 시도 | 실제 서버가 `Permission denied (publickey)`로 거부 |
| 공개 키 없는 인증 시도 | 실제 서버가 `Permission denied (publickey)`로 거부; 비밀번호 입력 없음 |
| 새 사용자 이름 검증 | 설치된 ssh가 `audit$probe`를 거부; `ssh -G`만 실행 |
| 실제 파일 전송 | 기본 SFTP 방식 SCP로 **131,072바이트** 업로드·다운로드, 세 위치의 SHA-256 일치 |
| 수용 검사 스크립트 | 실제 10.6p1 `sshd -T` 출력으로 두 스크립트의 awk 필터 **10개 검사 통과** |

이번에는 시험용 SSH 서버를 띄우지 않고 이미지에 설치된 운영 서버·helper를
검사했다. 계정·호스트 키·인증 정책은 변경하지 않았다. 파일 전송용 디렉터리와
데이터는 장치에서 제거했다. 최초 시험 도구는 새 홈에 `.cache`가 있다고 가정해
준비 단계에서 멈췄다. 홈 아래 독립 임시 디렉터리를 사용하도록 시험 도구만
수정한 뒤 전체 설치 검사를 다시 통과했다. 제품 수정은 없다.
