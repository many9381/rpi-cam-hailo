SRTP/SRTCP 검사는 정상 암호화 패킷의 인증·복호화와 수신기에서의 변조·재전송

운영 서비스가 유지됐다. 서버 내부의 패킷별 폐기 카운터를 검증한 것은 아니다.

## 시험 환경 보정과 빈 헤더의 의미

- 최초 로그 검사에서 `RTSPS`라는 대문자 문구를 기대했으나 현재 앱은 그 문구를
  출력하지 않았다. 카메라 시작 로그와 실제 TLS 연결의 SHA-256 challenge를
  각각 확인하도록 검사 도구를 보정했다. 제품 코드 변경은 없었다.
- 원시 네트워크의 `Session:` 또는 `Pipelined-Requests:` 빈 값은 GStreamer
  `gstrtspconnection.c:parse_line()`에서 헤더 목록에 추가하지 않는다. 따라서
  이 입력의 OPTIONS 200은 세션 선택이 없는 공개 OPTIONS와 같다. 초기 시험의
  "모든 빈 원시 헤더도 401"이라는 기대를 소스로 검증해 정정했다. 값이 있는
  선택 헤더는 실제 서버에서 401이다. 앱 단위 시험에서 메시지 객체에 직접
  넣어 유지한 빈 헤더는 401이며, 두 시험은 파서 전후의 서로 다른 입력이다.
- 호스트 SRTP 검사에 필요한 기존 시험용 libsrtp 공유 라이브러리를 별도
  Git 제외 디렉터리에 배치하고 self-test를 통과한 뒤 영상 검사에 사용했다.
  Pi에 새 패키지나 라이브러리를 설치하지 않았다.
