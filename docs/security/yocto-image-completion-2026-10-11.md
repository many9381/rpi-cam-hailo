# Yocto 통합 이미지 후속 작업 — 2026-10-11

후속 보안 작업: OpenSSH 10.6p1 반영과 새 이미지 검증은
[OpenSSH 보안 후속 조치](openssh-remediation-2026-10-11.md)에 기록했다.
아래의 기존 스캔 수치는 당시 이미지 결과로 보존하며 새 결과로 대체하지 않는다.

상위 `yocto-rpi5-cam-firmware`의 Hailo 카메라 개발 이미지에 대한 기록이다.
이미지 생성, 실제 장치 검증, 취약점 판정은 각각 별도 결과로 관리한다.
통합 이미지 생성과 호스트 검증, 최종 SBOM 검사를 마쳤다. 이후 SSD 설치와
Wi-Fi에서의 재부팅 3회·자동 실행 검증을 완료했다. 새 SSD의 첫 부팅에서는
시간 동기화 전 TLS 실패가 확인되어 별도 미해결 항목으로 기록한다.

## 반영한 변경

| 항목 | 변경 및 이유 |
| --- | --- |
| 앱 부팅 지연 | `camera-firmware.service`의 `network-online.target` 의존을 제거하고 `After=network.target`과 `/boot` 마운트 의존을 유지했다. Wi-Fi로 접속 가능해도 분리된 유선 인터페이스를 기다리던 약 120초 지연을 없애기 위한 변경이다. 실제 새 이미지의 시작 시간은 설치 후 측정한다. |
| 카메라 검사와 앱의 장치 충돌 | `test-camera.sh`가 최초 앱 실행 상태를 기록하고 직접 촬영 전 서비스를 정지하며 종료·실패·INT/TERM/HUP 시 원래 상태로 복구한다. 재부팅으로 자동 실행된 서비스도 같은 정책을 적용한다. |
| 검사 계정 권한 | 카메라 이미지에만 정확한 `/usr/bin/systemctl start camera-firmware.service` 및 `stop camera-firmware.service` 두 명령을 허용한다. 임의 systemctl 인수·일반 root 셸 권한은 추가하지 않았다. 정책 파일 모드는 0440이다. |
| 영상 판정 | raw H.264의 불완전한 시간 정보를 FPS로 해석하던 검사를 MP4 촬영 및 ffprobe JSON 검사로 변경했다. 실제 디코딩 프레임 수, 영상 길이, 평균/표시 프레임률, 코덱·해상도를 함께 확인한다. |
| 재부팅 후 SSH 신원 | 최초 확인한 호스트 키를 유지하고 주소가 바뀌어도 `HostKeyAlias`로 같은 키를 검사한다. 빌드 ID·프로필·루트 파일시스템 식별도 다시 검사한 뒤 서비스 명령을 실행한다. |
| 보안 검사 입력 | 카메라 프로필에 `SPDX_INCLUDE_VEX = "all"`을 설정해 레시피의 패치·CVE 판정 주석을 SBOM에 보존한다. 최신 DB 검사는 빌드 밖에서 실행하므로 CVE DB의 Git 이력이나 불필요한 네이티브 이미지를 빌드하지 않는다. |
| 빌드 입력 기록 | 새 빌드의 로컬 레이어·패치·kas·스크립트 내용과 해시를 보존하고 수집 시 변경 여부를 확인한다. Hailo DEB와 HEF는 해시만 기록한다. 키·인증 정보·Wi-Fi 비밀 설정은 소스 아카이브에 넣지 않는다. |

최초에 꺼져 있던 앱을 재부팅 후 검사 중단 시 켜진 채 남겨 두는 경로는
독립 검토에서 재현 후 수정했다. 복구 의무를 재부팅 전에 기록하고 이전 부팅의
신원 확인을 무효화한다. 재접속 실패나 신원 불일치 때는 서비스 명령을 보내지
않고 수동 복구 필요를 알린다. SIGKILL·호스트 전원 상실·연결 단절 상황에서
원격 복구를 보장하지 않으며 이런 경우 PASS를 만들지 않는다.

이번 개발 이미지에는 기존 로컬 컴파일러 레시피를 유지한다. 이 레시피는 Git
제외 상태라도 BitBake 입력이므로 비공개 provenance에 명시한다. 이 기록은
공개 배포 승인이나 비트 단위 재현성 보증이 아니다. Codex의 매 빌드 최신 안정
버전 선택, 외부 다운로드, 빌드 호스트 및 별도 비밀 설정은 재현 시 고려해야 한다.

배포자가 제공한 다운로드 SHA-256과 NVD 압축 해제 자료의 SHA-256·크기를 확인했다.
각각 NVD 404,108개, CVE List 404,202개 레코드를 보존했다. 스캔 시점까지의
모든 새 공개 자료를 실시간 포함한다는 의미는 아니다.

대규모 Git 이력 복제 대신 공식 스캐너의 CVE 파서와 버전 판정을 그대로 사용하는
SQLite 입력 어댑터를 사용했다. 영향 있음·수정됨·철회됨 레코드의 결과를 원래
파서와 비교했고 Yocto 패치 주석이 유지되는 것도 확인했다. 스캐너/의존성 버전,
DB·스크립트·입출력 해시, 실제 명령, 데이터 시각은 비공개 검사 증거에 보존한다.
스캐너나 제품 매핑을 바꾸면 DB 인덱스와 어댑터를 다시 검증해야 한다.

원본 결과는 수정하지 않는다. SPDX의 빌드 의존성과 실제 설치 패키지를 구분하기
위해 최종 이미지 package manifest와 교차 확인하고, 검토 결과는 별도
`triage-overlay.json`에 기록한다. 버전/제품 매칭은 실제 악용 가능성의 입증이 아니다.

### 2. 카메라 검사 UUID 조회: 수정 및 실기기 통과

실기기에서 `lsblk -no UUID /dev/sda2`는 빈 값을 반환하지만 udev의
`/dev/disk/by-uuid`에는 루트 장치 링크가 존재함을 재현했다.
`scripts/test-camera.sh`의 조회를 별도 읽기 전용
`scripts/lib/camera_root_identity.sh`로 분리하고 다음 처리를 적용했다.

- `lsblk`가 유효한 UUID를 주면 사용한다. UUID가 없거나 해당 열 조회가
  실패하면 실제 마운트 루트로 연결되는 udev 링크를 찾는다.
- 부트 파티션·다른 디스크·끊어진 링크·일반 파일은 사용하지 않는다.
  루트에 대응하는 UUID 링크가 여러 개이면 실패한다.
- UUID는 단일 ext4 UUID 형식이어야 한다. 공백·줄바꿈을 지워 서로 다른
